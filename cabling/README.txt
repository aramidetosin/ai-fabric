production AI fabric - cabling matrices
================================
Generated by gen_cabling.py from the decisions recorded on diagrams/ai-fabric-32gpu.excalidraw.
Nothing here is invented: where the sheet still carries a <placeholder>, so does the matrix.

  ./gen_oob.py                   > oob-cabling.csv             51 links
  python3 add_oob_sheet.py       -> adds the OOB sheet to ai-fabric-cabling.xlsx (first time, from the operator's upload)
  python3 sync_workbook.py       -> refreshes the workbook's Backend/Frontend/OOB rows + Summary counts from the generators

  ./gen_cabling.py backend       > backend-cabling.csv        384 links
  ./gen_cabling.py frontend      > frontend-cabling.csv         88 links  (gpu + ctrl leaves)
  ./gen_cabling.py frontend-gpu  > frontend-gpu-cabling.csv     64 links
  ./gen_cabling.py frontend-ctrl > frontend-ctrl-cabling.csv    24 links

Operator decisions 2026-09-24 (sheet rev 4): dual-homing = vPC Fabric Peering (notes say vPC, no longer ESI-LAG); three
frontend VLANs, each its own VRF (<data VLAN> / VRF k8s, <stor-mgmt VLAN> / VRF stor-mgmt, <bastion VLAN> / VRF bastion);
FlashBlade management moved from oob-sw ports 52-53 to the control leaves. Confirmed the same day: management = 1G via a QSA
adapter + 1000BASE-T SFP in the 100G leaf port; the FlashBlade data bond scope as drawn; backend uplinks BGP unnumbered.

backend-cabling.csv    all backend cabling
  256 x 400G  GPU node ConnectX-8 port 1 -> rail leaf, rail-optimised (NIC r -> be-leaf r)
              gpu n -> ethernet floor((n-1)/2) / (1 if n odd, 2 if n even), 2X400g breakout
  128 x 800G  rail leaf -> backend spines, contiguous block per spine:
              ethernet(48 + 4*(s-1) + k) -> be-spine s, k = 0..3
              spine side grouped by leaf, L1 first: port 4*(L-1) + k -> be-leaf L
  Port numbering 0-based (UfiSpace S9321-64E), as on the sheet.

frontend-cabling.csv    all frontend server cabling (GPU leaf pairs + control leaf pair)
  64 x 100G   gpu1-16 -> fe-gpu-leaf1 + fe-gpu-leaf2, gpu17-32 -> fe-gpu-leaf3 + fe-gpu-leaf4
              16 server ports per GPU leaf, Ethernet1/1..1/16; each pair starts again at 1/1
  22 x 100G   the control leaf pair, below (+ 2 FlashBlade management links)
  Every GPU node therefore has 10 data links in total: 8 x 400G backend rails + 2 x 100G frontend.

frontend-ctrl-cabling.csv    frontend CONTROL LEAF PAIR only
  22 x 100G   ctrl1-6, bastion, flashblade-1/2 -> fe-ctrl-leaf1 + fe-ctrl-leaf2
   2 x 1G     FlashBlade management, 1 port per appliance, no bond, <stor-mgmt VLAN>:
              flashblade-1 -> fe-ctrl-leaf1 Ethernet1/12, flashblade-2 -> fe-ctrl-leaf2 Ethernet1/12 (port PROPOSED:
              next free); QSA adapter + 1000BASE-T SFP in the 100G leaf port, RJ45 Cat6 to the appliance
  12 ports per leaf, Ethernet1/1..1/12. Ports 1-30 are the server range;
  31 and 32 carry the spine uplinks and are out of scope here.
  Every server has ONE LEG PER LEAF on the SAME port number of both leaves (the unbonded management ports excepted).
  Cisco Nexus naming Ethernet1/1..1/32.
  Out of scope by request: border leaves, firewall, leaf-spine uplinks (ports 31/32), OOB/BMC.

Port order on the control leaf follows the sheet's own listing (6 control + bastion + 4 FlashBlade + 1 FlashBlade management).
It is a straight sequence from Ethernet1/1; change the order in frontend_ctrl() if you want a different one.

oob-cabling.csv    OOB / BMC management cabling (added 2026-09-21)
  51 x 1G RJ45 Cat6 -> oob-sw, <OOB subnet>/24, gateway on the firewall
    ports  1-12   backend switches  be-leaf1-8, be-spine1-4  (1 management port each)
    ports 13-44   GPU nodes         gpu1-32                  (1 BMC each)
    ports 45-51   CPU nodes         ctrl1-6 + bastion        (1 BMC each)
    ports 52-53   free since 2026-09-24 (FlashBlade management moved to the control leaves)
  oob-sw model and port count are still to be selected; ports are sequential on one logical switch.
  NOT included: frontend switch management (8-10 ports; their mgmt0 also carries the vPC peer-keepalive) and the
  oob-sw uplink to the firewall (1 port). At 51 today, adding those lands near 62 - a 48-port switch does not fit.
